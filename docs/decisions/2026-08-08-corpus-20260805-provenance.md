## The four clauses, unpacked

**"historical label unverifiable by construction"** — `a025db1e…`, carried through WO-045→WO-050,
was produced by throwaway scripts that were never committed. Twenty candidate schemes failed to
reproduce it. It was never a claim about the corpus, only about a script that no longer exists.
See [[2026-08-07-an-integrity-figure-is-computed-by-committed-code]].

**"interval integrity witnessed by the capture-time per-segment manifest"** — `CORPUS_MANIFEST.json`
carries, for each of the 38 segments, a `sha256` with `hashed_at_capture: true`, computed by
`trading.data.corpus.sha256_file` at the moment each segment was closed. `tools/corpus_verify.py`
re-derives all 38 and matches. This is *not* the git witness D51 originally asked for: git has never
tracked `/captures/` — it is gitignored by deliberate policy (WO-042 §2.3), zero files in any
commit in all of history, so blob comparison has no operands.

**"manifest externally pinned from WO-051 by the v1 digest"** — this is the clause that closes the
self-description gap. The manifest hashes prove each *segment* is unaltered, but not the manifest
itself; an actor who rewrote a segment and its manifest entry would pass. The v1 digest
`e3ab1aec321a762848496af13557be0b419a4a3d7161b05b178f21095029ac10` covers **all 88 files including
the manifest**, and has been recomputed and matched at WO-051, WO-052 and WO-053. So the manifest is
pinned from outside itself, from a point in time before the current work. The two witnesses are
independent and cover each other's blind spot.

**"v1 canonical"** — `tools/corpus_digest.py`'s declared v1 scheme is the corpus digest of record.
`a025db1e…` is retired; it must not be cited again as evidence.

## Scope

This certifies the interval **WO-051 → present**, with per-segment integrity reaching back to
capture. It does **not** certify WO-045→WO-051 by git object identity, because that witness does not
exist. Anyone reading a pre-WO-051 report's `a025db1e…` citation should treat it as unverifiable.
